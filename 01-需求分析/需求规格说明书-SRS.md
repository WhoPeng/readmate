## 1. 引言

### 1.1 目的
定义「伴读」个人 AI 阅读器 MVP 的完整功能与非功能需求，作为开发、测试、验收的依据。

### 1.2 背景
传统阅读器记录"读到第几页"，笔记软件记录"记下了什么"，AI 工具记录"AI 总结了什么"。
本项目要记录的是：**我为什么读这本书 → 阅读中产生了什么想法 → 如何理解作者 → 哪里赞同/质疑 → 这本书最终对我产生了什么影响**。
软件的核心不是"阅读"，而是**人与一本书持续发生思想交互的过程**。

### 1.3 术语
| 术语 | 含义 |
|---|---|
| 伴读 | 应用内的大模型 AI，以"书旁朋友"的身份与用户讨论，不替代用户思考 |
| ReadingIntent | 阅读前访谈产出的阅读意图（动机/期待/关注主题/个人问题） |
| ChapterJournal | 每章反思完成后生成的章节阅读记录 |
| 「我与这本书」 | 全书完成后生成的思想档案报告 |
| 苏格拉底式追问 | AI 通过连续提问帮助用户形成自己理解的对话方式 |
| 来源标记 | 每条知识性内容标注其出处：[BOOK]/[AUTHOR]/[COMMUNITY]/[AI]/[READER] |

### 1.4 读者
开发（Claude）、需求方与验收人（用户本人）、后续维护者。

## 2. 总体描述

### 2.1 产品定位
一句话：**一个会陪你读书、先听你思考、再与你讨论，并记录你思想变化轨迹的个人 AI 阅读器。**

- 形态：单机桌面应用（Windows 优先），无云端、无账号、无社交。
- 运行：用户自行提供大模型 API（不绑定任何厂商）。
- 风格：安静、沉浸、克制；阅读时书是主角，AI 像坐在旁边的朋友，不是弹窗客服。

### 2.2 用户与场景
- 唯一用户：本人（单人本地使用）。
- 典型场景：导入一本 EPUB → 读前访谈 → 逐章阅读 → 每章完成后与 AI 讨论 → 读完整本生成「我与这本书」→ 若干本后浏览自己的阅读档案。

### 2.3 运行环境
- Windows 11（第一阶段）；EPUB 2/3 格式；需要网络时仅用于调用用户配置的 AI API。

### 2.4 范围与边界（MVP）
**做（MVP 范围）**：EPUB 导入解析、阅读器（阅读/设置/高亮/笔记/书签）、AI 配置、阅读前访谈、章节伴读反思、章节 Journal、全书报告「我与这本书」、个人阅读档案（简化版）、数据备份导出。

**明确不做（本版本）**：PDF、社区账号/社交/讨论区、复杂推荐算法、搜索盗版书籍、自动下载书籍全文、知识图谱、多 Agent 协作、本地大模型、语音伴读、OCR、云同步、移动端、复杂统计、插件市场、跨书相似观点关系网络（二期）。

### 2.5 产品核心原则（所有功能的最高约束）
| 编号 | 原则 |
|---|---|
| P1 | **AI 不能替代阅读者思考**：先让用户表达理解，AI 之后才能给出作者原意、肯定/纠正/补充 |
| P2 | **AI 伴读不是问卷**：必须动态追问，理解用户答话的深层含义 |
| P3 | **合理分歧 ≠ 理解错误**：用户正确理解作者但不同意，是最有价值的阅读状态之一 |
| P4 | **不允许伪造**：不得伪造社区观点百分比、不得把 AI 推测说成作者观点、不得伪造任何数据 |
| P5 | **来源标记**：所有知识性内容标注 [BOOK]/[AUTHOR]/[COMMUNITY]/[AI]/[READER] |
| P6 | **阅读时 AI 安静**：默认不打扰，仅在用户主动调用或完成章节后进入伴读流程 |
| P7 | **数据本地优先**：书籍与用户数据保存在本机；AI 只发送必要的上下文（可配置） |
| P8 | **API Key 安全**：使用操作系统安全存储，不明文落盘 |

## 3. 功能需求

> 每条格式：描述 → 验收标准（可测试）。优先级：M=必须（MVP 含） / S=应有（可后续） / C=可以有。

### 模块 A：书籍导入与解析

**FR-01 导入 EPUB 文件**（M）
- 描述：用户通过界面选择本地 EPUB 文件导入；导入后自动解析并进入书架。
- 验收标准：
  - [ ] 选择合法 EPUB 后 5 秒内完成解析并出现在书架（普通大小书籍）
  - [ ] 解析出：书名、作者、封面、目录（如存在）、章节列表
  - [ ] 损坏/非法文件给出明确中文错误提示，不影响书架上其他书
  - [ ] 重复导入同一本书（按文件指纹）时提示已存在，不产生重复条目

**FR-02 书籍存储与数据模型**（M）
- 描述：建立统一内部 Book 模型（id、title、author、cover、format、metadata、chapters、readingProgress），书籍文件统一复制到应用数据目录管理。
- 验收标准：
  - [ ] 导入后删除源文件，应用内仍可完整阅读（数据自持）
  - [ ] 章节内容同时保存 HTML 与纯文本两种形式供不同场景使用

**FR-03 书籍列表与详情**（M）
- 描述：书架展示全部书籍（封面、书名、作者、阅读进度）；书籍详情页展示元数据、目录树、"开始/继续阅读"。
- 验收标准：
  - [ ] 列表按最近阅读排序，进度显示正确
  - [ ] 详情页目录树层级与 EPUB 目录一致，可展开/折叠
  - [ ] 点击目录项跳转到对应章节

### 模块 B：阅读器

**FR-04 阅读核心**（M）
- 描述：支持翻页/滚动、章节导航（目录/上一章/下一章/键盘）、阅读进度显示与自动保存（章节+位置），启动时恢复上次阅读位置。
- 验收标准：
  - [ ] 阅读流畅（长章节渲染 ≤ 2 秒，翻页无卡顿）
  - [ ] 中途退出重开，精确恢复到上次位置
  - [ ] 进度百分比随阅读实时更新

**FR-05 阅读设置**（M）
- 描述：字体大小（≥5 档）、行距（≥3 档）、阅读主题（≥3 种含夜间模式）；设置实时生效并持久化。
- 验收标准：
  - [ ] 修改设置立即生效，重启应用后保持
  - [ ] 夜间模式下正文与界面均无刺眼高亮

**FR-06 高亮**（M）
- 描述：选中正文文字可添加高亮（支持多种颜色）；高亮持久化（含锚点定位），可在"标注列表"中查看并跳转。
- 验收标准：
  - [ ] 高亮在重启后完整保留、位置准确
  - [ ] 同一段落可叠加多色高亮；可删除
  - [ ] 标注列表点击可跳转到原文位置

**FR-07 笔记**（M）
- 描述：选中文字可添加笔记（绑定位置）；笔记可编辑、删除；可独立添加不绑定的章内笔记。
- 验收标准：
  - [ ] 笔记与位置绑定，跳转准确
  - [ ] 编辑/删除后数据同步更新
  - [ ] 笔记内容参与伴读 AI 的上下文（见 FR-13）

**FR-08 书签**（M）
- 描述：可在当前阅读位置添加/删除书签，书签列表可跳转。
- 验收标准：
  - [ ] 书签添加/删除/跳转功能完整，重启后保留

**FR-09 阅读中 AI 安静**（P6 落地）（M）
- 描述：阅读过程中 AI 不主动弹出任何内容；仅"读完本章"按钮与用户主动呼出伴读面板时进入对话。
- 验收标准：
  - [ ] 连续阅读 10 分钟无任何 AI 打扰
  - [ ] 伴读面板默认隐藏，可手动开关

### 模块 C：AI 配置

**FR-10 多厂商 API 配置**（M）
- 描述：支持配置 OpenAI-compatible API（OpenAI/DeepSeek/OpenRouter/Ollama/Moonshot 等）、Anthropic；字段：Provider、API Key、Base URL、Model、参数（temperature 等）；区分主伴读模型与快速模型（MVP 至少预留配置位）。
- 验收标准：
  - [ ] 至少两种厂商可实测连通（用真实 Key 验证）
  - [ ] 切换厂商无需改代码，界面完成切换
  - [ ] 主模型/快速模型配置位均存在（快速模型 MVP 可不启用）

**FR-11 API Key 安全存储**（M）
- 描述：Key 使用操作系统凭据管理器（keyring）保存；界面只显示掩码。
- 验收标准：
  - [ ] 应用数据目录、配置文件、日志中搜索不到明文 Key
  - [ ] 重新输入可更换 Key；已存 Key 回显为掩码

**FR-12 连接测试**（M）
- 描述：配置页提供"测试连接"，真实调用一次并显示结果与延迟。
- 验收标准：
  - [ ] Key 错误/网络不通/限流分别给出可理解的中文错误提示
  - [ ] 测试成功时显示所用模型名与响应耗时

### 模块 D：阅读前访谈

**FR-13 访谈触发与流程**（M）
- 描述：新书首次打开时启动简短 AI 访谈（3~5 问）：动机 → 期待收获 → 关注主题 → 个人疑问；AI 逐问等待回答，基于上一答动态提问（非固定模板）；可中途退出，断点可续（或明确提示重来）。
- 验收标准：
  - [ ] 访谈问题数量 3~5 个，AI 每个问题引用用户上一答
  - [ ] 完成后生成 ReadingIntent 并保存（motivation / expectedGain / interestedTopics / personalQuestions / emotionalContext）
  - [ ] 访谈可跳过（明确"跳过访谈直接阅读"入口）
  - [ ] 访谈中 AI 不主动介绍书籍内容（只围绕用户动机提问）

**FR-14 ReadingIntent 查看与编辑**（M）
- 描述：书籍详情页展示访谈结果，用户可手动编辑各字段；可重新访谈。
- 验收标准：
  - [ ] 编辑保存后生效，重新访谈会生成新版本（旧版本可追溯）

### 模块 E：章节伴读反思（核心闭环）

**FR-15 读完本章触发**（M）
- 描述：阅读器提供"读完本章"按钮；点击后伴读面板进入反思流程，AI 基于本章内容、阅读动机、高亮、笔记提出 1~3 个分层问题（感受层 → 理解层 → 联系自己层），一次只问一个。
- 验收标准：
  - [ ] 问题引用本章真实内容与用户高亮（非空泛模板）
  - [ ] 问题顺序符合"感受→理解→联系自己"层次
  - [ ] 反思流程状态可视化（第几步/共几步），可随时中断

**FR-16 动态追问**（P2 落地）（M）
- 描述：AI 根据用户回答动态追问（如"你不同意的是结论，还是推导过程？"）；追问默认不超过 3 轮；用户可主动结束。
- 验收标准：
  - [ ] 样例验证：用户说"我不同意作者"时，AI 追问分歧层次而非直接反驳
  - [ ] 追问轮数不超上限，超限自动收敛
  - [ ] 用户明确结束（如"我没有更多想法了"）后流程正常进入下一步

**FR-17 作者原意分析与对照**（M）
- 描述：用户表达完成后（非之前），AI 输出：作者核心观点、主要论据、论证过程、隐含前提、结论；并与用户观点对照，给出四类结论：一致 / 部分一致 / 理解偏差 / 合理分歧。
- 验收标准：
  - [ ] 四类结论判定正确（用 3 组固定样例对话验证）
  - [ ] 合理分歧情况下，AI 明确肯定"你正确理解了作者，但持不同立场"（不得定性为错误）

**FR-18 章节 Journal**（M）
- 描述：反思完成后生成 ChapterJournal：章节、阅读时长、我的感受、我的理解、我的疑问、AI 反馈、作者立场、一致程度、分歧、误解、是否改变想法、最终想法；以结构化页面展示，最终想法可编辑。
- 验收标准：
  - [ ] Journal 字段完整落库（chapter_journals 表）
  - [ ] 展示结构清晰（我的理解/我的感受/我的疑问/AI 反馈/我的最终想法）
  - [ ] 编辑最终想法后保存更新
  - [ ] 同一章可重复反思（覆盖或另存版本，二选一并有明确提示）

**FR-19 思想变化轨迹**（M）
- 描述：记录"阅读前 → 初始理解 → 讨论后 → 最终理解"的变化，可随「我与这本书」展示。
- 验收标准：
  - [ ] 轨迹数据真实来自访谈/Journal 记录，非 AI 现场编造
  - [ ] 轨迹随反思进行逐步更新

**FR-20 来源标记**（P5 落地）（M）
- 描述：伴读输出中，知识性内容按来源标注：作者在书中观点 [BOOK]、作者公开表达 [AUTHOR]（二期）、社区讨论 [COMMUNITY]（二期）、AI 分析 [AI]、用户观点 [READER]。
- 验收标准：
  - [ ] 作者原意分析标 [BOOK]，AI 补充分析标 [AI]，界面可见区分
  - [ ] 无 [AUTHOR]/[COMMUNITY] 来源时不得出现此类内容（不伪造）

### 模块 F：全书闭环与阅读档案

**FR-21 「我与这本书」**（M）
- 描述：全书完成后生成报告，包含 10 项：为什么读它、阅读前的我、最重要的时刻、共鸣的观点、反对的观点、曾经误解、改变的想法、作者真正想表达的、是否接受作者、这本书对我的影响；最终形成"阅读后的我"。
- 验收标准：
  - [ ] 10 项内容齐全，每项有可追溯的数据来源（章节/对话）
  - [ ] 内容可编辑；重新生成时保留已编辑版本（版本区分）
  - [ ] 未完成全书时无此报告入口

**FR-22 个人阅读档案（MVP 简化版）**（M）
- 描述：书架增强为档案视图：每本书显示进度与完成状态；"我的想法"（全部章节最终想法聚合浏览）；"我的问题"（访谈与反思中提出的问题）；主题标签（自动提取 1~3 个，可手动编辑）。
- 验收标准：
  - [ ] 多本书数据视图互不串扰
  - [ ] 标签编辑持久化

**FR-23 数据备份与导出**（M）
- 描述：将数据库与书籍目录打包导出为单一备份文件；支持导入恢复。
- 验收标准：
  - [ ] 导出文件包含全部书籍与阅读数据，导入后完整恢复
  - [ ] 备份文件不含明文 API Key

### 模块 G：AI 调用管理

**FR-24 AI 调用可追踪**（M）
- 描述：每次 AI 调用记录：时间、模型、Provider、输入/输出 tokens、耗时、所属场景（访谈/提问/分析/报告）。
- 验收标准：
  - [ ] 全部记录落库（ai_messages），可查询最近调用
  - [ ] 无任何调用绕过记录通道

**FR-25 AI 输出可中断与可纠错**（M）
- 描述：流式输出期间用户可停止生成；AI 输出后用户可反馈"不对"，AI 重新生成（或用户直接编辑）。
- 验收标准：
  - [ ] 停止生成后流程状态正常，不产生半截数据落库
  - [ ] 重新生成不重复落库（覆盖语义）

## 4. 非功能需求

| 编号 | 类别 | 需求 | 验收标准 |
|---|---|---|---|
| NFR-01 | 性能 | 导入解析 | 普通 EPUB（<5MB）导入全程 ≤ 5 秒 |
| NFR-02 | 性能 | 阅读流畅 | 章节渲染 ≤ 2 秒；翻页/滚动无卡顿 |
| NFR-03 | 性能 | AI 响应 | 流式首 token ≤ 5 秒（正常网络）；对话逐字渲染 |
| NFR-04 | 安全 | 密钥 | API Key 仅存于系统凭据管理器（见 FR-11） |
| NFR-05 | 隐私 | 数据边界 | 书籍/笔记/记录全部本地存储；发送给 AI 的上下文可配置（默认仅当前章节+动机+高亮/笔记+摘要，不含全书） |
| NFR-06 | 可靠性 | 数据安全 | 阅读进度/高亮/笔记实时落库；异常退出不丢数据 |
| NFR-07 | 兼容性 | 格式 | 支持 EPUB 2/3；乱码/异常书籍给出错误提示 |
| NFR-08 | 可用性 | 断网行为 | 断网时阅读/高亮/笔记/进度全部可用，仅 AI 功能提示"网络不可用" |
| NFR-09 | 可维护性 | 架构 | 分层架构；AI Provider 接口抽象；核心服务可单元测试（覆盖率 ≥ 70%） |
| NFR-10 | 可维护性 | 文档 | 每步开发产出对应文档更新；README 含运行与已知问题 |

## 5. 外部接口

| 接口 | 说明 |
|---|---|
| AI API | OpenAI-compatible（OpenAI/DeepSeek/OpenRouter/Ollama 等）＋ Anthropic 原生协议；流式（SSE）与非流式 |
| 文件格式 | 输入 EPUB（zip + OPF/NCX/XHTML 结构）；输出为内部统一数据模型 |
| 系统能力 | Windows 凭据管理器（keyring）；文件系统（数据目录读写） |

## 6. 数据需求摘要

核心实体：books、chapters、reading_intents、highlights、notes、bookmarks、chapter_journals、reader_thoughts、reader_questions、ai_messages、settings、reader_memories、book_memories（详细 Schema 见 `02-设计/项目设计-Phase0.md` 第 9 节）。

## 7. 整体验收方案

1. **测试书**：准备 2 本真实 EPUB（一本标准排版含目录、一本民间转制兼容性较差）。
2. **全流程走查**（验收人=用户本人，至少 2 轮）：
   - 配置 AI（真实 Key）→ 测试连接成功
   - 导入两本书 → 书架/详情正确
   - 读第一本：完整访谈 → 阅读 3 章（含高亮/笔记/书签/设置/夜间模式/进度恢复）
   - 每章完成反思：提问 → 回答 → 追问 → 对照 → Journal 生成
   - 读完最后一章 → 生成「我与这本书」
   - 第二本快速走通导入→阅读→单章反思（验证多书隔离）
   - 浏览"我的想法/我的问题/标签"
   - 导出备份 → 导入恢复验证
3. **验收结论**：P0/P1 清零、验收清单通过 → 宣布 MVP v1.0 完成。
