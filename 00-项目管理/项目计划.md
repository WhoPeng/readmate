> 状态：**MVP 开发完成（20/20 步）** ｜ 制定日期：2026-08-30 ｜ **版本：v1.2（开发完成，同步更新）**

## 1. 项目章程

| 项 | 内容 |
|---|---|
| 项目名称 | 伴读（ReadMate） |
| 一句话定位 | 一个会陪你读书、先听你思考、再与你讨论，并记录你思想变化轨迹的个人 AI 阅读器 |
| 核心问题 | 读完一本书后，用户获得了什么？理解发生了什么变化？ |
| 项目形态 | **单机桌面应用**（Windows 优先），用户自行接入大模型 API，无云端部署 |
| 技术栈 | Electron + React/TypeScript + epub.js（前端/阅读器）｜ Python FastAPI + SQLite（数据与解析）｜ AI Provider 层在 Electron 主进程（TS，参考 Cherry Studio） |
| 开发方法 | 迭代增量：六个阶段依次推进，每阶段结束可运行、可验收（微型瀑布） |
| 成功标准 | ① 用一本真实 EPUB 走通"导入 → 阅读 → 章节反思 → 全书报告"全流程；② AI 全程"先问后答"，不替用户思考；③ 所有 API Key 安全存储；④ 全程 AI 调用可追溯、内容带来源标记 |
| 明确不做 | 云同步、社区/社交、多 Agent、PDF（二期）、知识图谱（后期）、本地模型（见需求文档边界） |
| 团队 | 用户（产品/需求方/验收） + Claude（架构/开发/测试） |

## 4. 分步开发计划（一个步骤一个步骤）

> 每步结构：目标 → 任务 → 产出 → 验收标准（DoD）→ 估算 → 前置依赖。
> **每步结束时项目必须可运行**（铁律，不允许"半成品跨步"）。
> **每步结束时相关文档同步更新**（铁律，含本计划与设计文档的变更记录）。

### 步骤 01：初始化项目仓库结构
- **目标**：建立规范 monorepo 骨架，为后续所有代码定好"家"。
- **任务**：
  1. 创建目录：`backend/`（Python）、`electron/`（主进程）、`frontend/`（React）、`shared/`（TS 类型）、`data/`、`docs/`、`tests/`
  2. `backend/pyproject.toml` + 虚拟环境，安装 FastAPI/Uvicorn/SQLAlchemy/ebooklib
  3. `frontend/package.json` + Vite + React + TS 初始化（`npm create vite` 骨架）
  4. 编写根 `README.md`（项目说明 + 三进程如何跑起来）
  5. 初始化 Git 仓库，提交首个 commit
- **产出**：三部分都能独立安装/启动骨架的仓库。
- **验收标准**：
  - [ ] 目录结构与设计文档第 1 节一致
  - [ ] 后端虚拟环境 `pip install -e .` 无报错；前端 `npm install && npm run dev` 能起 Vite
  - [ ] Git 仓库已有首个 commit（含 .gitignore）
- **估算**：1 天 ｜ **依赖**：M0 架构评审通过

### 步骤 02：后端骨架（FastAPI + SQLite）
- **目标**：Python 数据层能启动、连库、提供健康检查。
- **任务**：
  1. FastAPI 应用入口 + 生命周期（启动时初始化数据库、建 data/ 目录）
  2. SQLAlchemy 引擎与 Session 管理（SQLite 位于 `data/readmate.db`）
  3. `metadata.create_all` 建表（books/chapters 先行，其余随步骤推进添加）
  4. `GET /api/health`（返回版本 + 数据库状态）；CORS 允许本地前端（开发期）
- **产出**：可启动的 API 服务 + 数据库文件。
- **验收标准**：
  - [ ] `uvicorn` 启动无报错，`/api/health` 返回 200
  - [ ] 数据库自动创建，books/chapters 表存在
  - [ ] 后端分层目录（api/services/models/infrastructure）就位
- **估算**：0.5 天 ｜ **依赖**：步骤 01

### 步骤 03：Electron 壳 + 前端骨架（三通）
- **目标**：Electron 窗口显示 React 页面，并成功调用 Python 后端（三进程链路通）。
- **任务**：
  1. Electron main：创建窗口（开发期加载 Vite dev server，生产期加载构建产物）
  2. main 进程启动时 spawn Python 后端子进程（uvicorn），窗口关闭时优雅结束（防孤儿进程、端口复用检测）
  3. preload 暴露最小 IPC 面（版本信息、ping）
  4. React 首页显示"后端连接正常"（经 preload 或 http 调用 /api/health）
- **产出**：`npm run dev` 一键启动的桌面窗口，显示后端健康状态。
- **验收标准**：
  - [ ] 启动后窗口出现，健康状态显示"正常"
  - [ ] 关闭窗口后 Python 进程退出（任务管理器验证），再次启动无端口冲突
  - [ ] 开发热更新（Vite HMR）生效
- **估算**：1.5 天 ｜ **依赖**：步骤 02

### 步骤 04：EPUB 元数据解析 + 渲染可行性验证
- **目标**：确认 EPUB 全链路技术可行：Python 解析元数据 + epub.js 渲染正文。
- **任务**：
  1. ebooklib 解析：书名、作者、封面、出版社、目录树（TOC）、章节清单 → 统一数据模型
  2. 文件指纹（sha256）用于去重；文件复制管理到 `data/books/`
  3. **渲染可行性 spike**：临时页面用 epub.js 加载一本测试书，验证渲染/翻页/CFI 获取（`cfiFromRange` 取高亮锚点）
  4. 单元测试：2 本真实 EPUB（一本标准、一本兼容性差的）验证解析
- **产出**：解析模块 + 渲染 spike 结论（记录到设计文档第 4 节）。
- **验收标准**：
  - [ ] 测试书解析出书名/作者/封面/目录/章节清单
  - [ ] 无 TOC 的 EPUB 按文档顺序生成章节清单
  - [ ] epub.js 能渲染测试书并正确返回 CFI（锚点可行性验证通过）
  - [ ] 解析失败返回结构化错误（不是裸异常）
- **估算**：1.5 天 ｜ **依赖**：步骤 02
- **风险提示**：若 epub.js 渲染与 Python 元数据不一致（章节顺序/层级），以 epub.js 实际渲染为准，Python 只做书架级元数据（已按此设计）。

### 步骤 05：导入功能 + 书籍入库 + 书架
- **目标**：选择 EPUB → 解析 → 入库 → 书架可见。
- **任务**：
  1. `POST /api/books/import`（接收文件 → 指纹去重 → 解析元数据 → 存文件+入库）
  2. 前端导入对话框（选文件、进度、错误提示）
  3. `GET /api/books` 列表接口（封面/书名/进度字段）
- **产出**：可从书架看到导入的书。
- **验收标准**：
  - [ ] 导入后书架出现该书（封面/书名/作者正确）
  - [ ] 重复导入提示已存在，不产生重复条目
  - [ ] 损坏文件有明确中文错误提示，不影响其他书
- **估算**：1 天 ｜ **依赖**：步骤 04

### 步骤 06：书籍详情页 + 目录树
- **目标**：详情页展示元数据与目录导航。
- **任务**：
  1. `GET /api/books/{id}` 详情接口（含目录树）
  2. 详情页：封面、信息区、目录树（嵌套展开/折叠）
  3. "开始阅读 / 继续阅读"入口（跳阅读器）
- **产出**：书籍详情页。
- **验收标准**：
  - [ ] 目录树结构与 EPUB 层级一致
  - [ ] 点目录项跳转阅读器正确章节（CFI）
- **估算**：0.5 天 ｜ **依赖**：步骤 05

### 步骤 07：epub.js 阅读器集成（正文渲染）
- **目标**：epub.js 渲染正文，支持分页/翻页/章节切换（阅读器地基）。
- **任务**：
  1. 阅读器核心组件：`book.load(文件URL)` → 渲染 → 分页视图（页面模式）
  2. 章节导航：上一章/下一章/目录跳转（epub.js spine + `display()`）
  3. 阅读位置获取（`book.locations` + CFI）与持久化接口
  4. 正文字体/排版基础样式（阅读 CSS 独立文件，主题变量化）
- **产出**：可翻阅一本书的阅读器核心。
- **验收标准**：
  - [ ] 测试书全部章节可渲染、翻页流畅
  - [ ] 章节切换正确，位置信息可读取
  - [ ] 内嵌图片正常显示
- **估算**：1.5 天 ｜ **依赖**：步骤 05、06（书与元数据）
- **参考**：Readest / Koodo Reader 的 epub.js 封装代码。

### 步骤 08：阅读器界面（三栏 + 导航 + 进度恢复）
- **目标**：完整阅读器界面与阅读行为。
- **任务**：
  1. 三栏布局：左目录（可折叠）｜中正文｜右伴读面板（默认隐藏）
  2. 顶栏：书名、章节、进度百分比、设置入口、伴读开关
  3. 键盘快捷键（方向键翻页、Esc 收起面板）
  4. 进度自动保存（CFI + 百分比，防抖写入 `books.progress_cfi`）
  5. 启动"继续上次阅读"（最近一本 + 位置恢复）
- **产出**：可正常阅读并记住进度的阅读器。
- **验收标准**：
  - [ ] 翻页流畅无卡顿；进度条联动正确
  - [ ] 中途退出重开，精确恢复位置
  - [ ] 伴读面板开合不影响正文渲染
- **估算**：1.5 天 ｜ **依赖**：步骤 07

### 步骤 09：阅读设置（字体/行距/主题/夜间模式）
- **目标**：阅读舒适度设置，持久化。
- **任务**：
  1. 设置面板：字体大小（5 档）、行距（3 档）、主题（light/sepia/dark）
  2. 实时生效 + 写入 settings 表；重启保持
  3. 夜间模式联动（正文 CSS 变量 + 界面主题）
- **产出**：可个性化设置的阅读体验。
- **验收标准**：
  - [ ] 设置立即生效且重启保持
  - [ ] 三主题下正文可读性良好
- **估算**：0.5 天 ｜ **依赖**：步骤 08

### 步骤 10：高亮 + 笔记 + 书签（CFI 锚点）
- **目标**：阅读中留下自己的痕迹（伴读的数据基础）。
- **任务**：
  1. 选区工具条：选中文字 → 高亮（3 色）/ 添加笔记 / 复制
  2. 高亮持久化：`cfiFromRange()` 生成 CFI 存 `highlights` 表；渲染时 `getRange(cfi)` 还原高亮 DOM
  3. 笔记（绑定高亮或独立位置）、书签（章节 + CFI）
  4. 侧边"我的标注"列表（当前章高亮/笔记，点击跳转）
- **产出**：可高亮、写笔记、加书签的完整阅读器。
- **验收标准**：
  - [ ] 高亮/笔记重启后完整保留、位置准确
  - [ ] 翻页/切章后再回来，高亮不丢失
  - [ ] 删除有确认且数据正确删除
- **估算**：1.5 天 ｜ **依赖**：步骤 08
- **参考**：Koodo Reader 的高亮实现（CFI 还原包裹 `<mark>`）；风险已较 v1.0 大幅下降（CFI 是标准定位）。

### 步骤 11：AI Provider 层（TS，参考 Cherry Studio）
- **目标**：统一的多厂商接入层，位于 Electron 主进程。
- **任务**：
  1. `shared/types.ts`：ProviderConfig、ChatRequest、错误码等契约类型
  2. `electron/ai/provider.ts` 统一接口（chatStream/chat/testConnection）+ 错误模型
  3. `openaiCompat.ts`（OpenAI/DeepSeek/OpenRouter/Ollama…，`/chat/completions` 流式）与 `anthropic.ts`（Claude messages API）适配器
  4. IPC 桥（preload）：`ai.chatStream / ai.testConnection / ai.cancel`
  5. vitest 单测：mock 响应验证两家协议消息格式与流式解析
- **产出**：可插拔 AI 接入层（参考 Cherry Studio 架构）。
- **验收标准**：
  - [ ] 新增厂商 = 新增适配器，业务层零改动
  - [ ] 流式逐块回调正确；三种错误（鉴权/限流/网络）返回明确错误码
  - [ ] renderer 拿不到明文 Key（Key 只在 main 进程）
- **估算**：2 天 ｜ **依赖**：步骤 03

### 步骤 12：AI 配置页 + 密钥安全存储
- **目标**：界面配置 AI，密钥安全保存。
- **任务**：
  1. Settings 页：Provider 类型、Base URL、Model（内置各厂商常用模型表 + 手动输入）、参数（temperature 等）
  2. Key 经 safeStorage 加密后存 settings 表（main 进程内加解密，renderer 只见掩码）
  3. 测试连接按钮（走 IPC → provider.testConnection → 显示结果与延迟）
  4. 模型切换联动（按厂商显示模型清单）
- **产出**：完整可用的 AI 配置体验。
- **验收标准**：
  - [ ] 用真实 Key 测试连接成功
  - [ ] 数据库中 Key 为密文；renderer 与日志均无明文
  - [ ] 更换 Provider 后模型列表联动正确
- **估算**：1 天 ｜ **依赖**：步骤 11

### 步骤 13：Context 组装 + 流式对话通道
- **目标**：把"书 + 用户 + 历史"组装成正确的 Prompt（伴读大脑）。
- **任务**：
  1. `contextBuilder.ts`：按设计文档第 6 节预算组装（System 原则 + 用户画像 + 章节 + 高亮/笔记 + 历史反思摘要）
  2. 流式对话链路：renderer 发起 → main 调 provider → token 块经 IPC 回传 → 界面逐字渲染；可中断
  3. Prompt 模板库（interview/reflect_questions/follow_up/author_position/book_report 五类，JSON Schema 约束结构化输出场景）
  4. 调用记录：main 每次调用后 `POST /api/ai/messages` 落库（tokens/耗时/模型）
- **产出**：AI 对话通道 + 上下文组装框架。
- **验收标准**：
  - [ ] 流式逐字渲染无卡顿，可中断且状态不脏
  - [ ] 每次调用完整记录（ai_messages 可查）
  - [ ] 超长章节触发截断策略（不报错）
  - [ ] 结构化输出解析失败自动重试一次
- **估算**：2 天 ｜ **依赖**：步骤 11、12

### 步骤 14：阅读前访谈
- **目标**：读一本书前，先弄清"我为什么读它"。
- **任务**：
  1. 新书首次打开 → 触发访谈（动机 → 期待 → 主题 → 疑问，AI 逐问逐答，动态追问）
  2. 访谈状态机（TS sessions.ts）：状态持久化经后端（可续谈）；"跳过访谈"入口
  3. AI 结构化输出 ReadingIntent JSON → 经 REST 落库（版本化），详情页展示、可编辑、可重访
  4. 访谈中 AI 不介绍书的内容（只围绕动机）
- **产出**：可完整走完"读前访谈"并生成阅读意图。
- **验收标准**：
  - [ ] 访谈 ≤5 问，每问基于上一答（非固定模板）
  - [ ] ReadingIntent 字段完整、可编辑；中断可续
  - [ ] 跳过访谈后其余流程不受影响
- **估算**：1.5 天 ｜ **依赖**：步骤 13

### 步骤 15：章节完成 → AI 主动提问
- **目标**：读完一章后，AI 先请用户表达（核心原则落地）。
- **任务**：
  1. 阅读器底部"读完本章"按钮 → 打开伴读面板进入反思流程
  2. 反思状态机（TS）：AI 基于（本章 + 动机 + 高亮/笔记）提出 1~3 个分层问题（感受/理解/联系自己），一次一个
  3. 面板状态指示（第几步/共几步）；可中断、可恢复
- **产出**：读完一章后 AI 主动引导反思。
- **验收标准**：
  - [ ] 提问引用本章真实内容与用户高亮（非空泛模板）
  - [ ] 问题层次顺序正确；中断恢复正常
- **估算**：1.5 天 ｜ **依赖**：步骤 13、14（访谈数据参与上下文）

### 步骤 16：动态追问（苏格拉底式对话）
- **目标**：AI 根据回答持续追问，帮助用户形成自己的理解。
- **任务**：
  1. 追问逻辑：AI 输出"提问文本 + action（追问/下一问/结束）"，状态机按 action 流转
  2. 追问上限控制（默认 3 轮）；用户可主动结束（"我没有更多想法了"）
  3. 对话历史按章节持久化（ai_messages 关联 session）
- **产出**：真正的"讨论感"对话（不是问答问卷）。
- **验收标准**：
  - [ ] 对"我不同意作者"的回答，AI 追问分歧层次而非反驳
  - [ ] 追问轮数不超上限，超限自动收敛
  - [ ] 用户结束表达时流程正常进入下一步
- **估算**：1 天 ｜ **依赖**：步骤 15

### 步骤 17：作者原意分析 + 对照 + 章节 Journal
- **目标**：用户表达完成后，AI 对照作者原意，产出章节记录。
- **任务**：
  1. "我思考完了" → AI 生成作者原意分析（核心观点/论据/论证/隐含前提/结论）
  2. 对照输出四类结论：一致/部分一致/理解偏差/合理分歧（模板注入"合理分歧≠错误"规则）
  3. 组装 ChapterJournal（感受/理解/疑问/AI 反馈/立场/一致程度/分歧/误解/最终想法）→ 落库
  4. 前端"章节记录"视图（结构化展示 + 最终想法可编辑）；来源标记（[BOOK]/[AI]/[READER]）
  5. 3 组固定样例验证四类结论判定（vitest）
- **产出**：每章一份可回看的阅读记录。
- **验收标准**：
  - [ ] 四类结论判定正确（样例验证通过）
  - [ ] Journal 字段完整落库、展示清晰；编辑保存生效
- **估算**：2 天 ｜ **依赖**：步骤 16

### 步骤 18：「我与这本书」（全书完成报告）
- **目标**：读完最后一章后，生成整本书的思想记录。
- **任务**：
  1. 最后一章 Journal 完成后触发"全书完成"状态
  2. AI 汇总全书 10 项内容（动机回顾/前后对比/关键时刻/共鸣/反对/误解/改变/作者本意/最终立场/影响）
  3. "思想变化轨迹"可视化（阅读前 → 讨论中 → 最终，数据来自真实记录）
  4. 报告可重新生成（保留已编辑版本）
- **产出**：「我与这本书」完整报告。
- **验收标准**：
  - [ ] 10 项齐全，每项有可追溯来源
  - [ ] 轨迹数据来自记录（非编造）；重新生成不覆盖已编辑版本
- **估算**：2 天 ｜ **依赖**：步骤 17

### 步骤 19：个人阅读档案首页
- **目标**：多本书的阅读档案汇总（MVP 简化版）。
- **任务**：
  1. 书架增强：进度/已读章节/完成状态
  2. "我的想法"视图（全部最终想法按书聚合）；"我的问题"视图
  3. 主题标签（自动提取 1~3 个 + 手动编辑）
- **产出**：个人阅读档案首页。
- **验收标准**：
  - [ ] 多本书数据隔离正确；标签编辑持久化
- **估算**：1.5 天 ｜ **依赖**：步骤 17

### 步骤 20：端到端验收 + 打磨
- **目标**：用真实书走完整流程，修复问题，冻结 MVP。

  - [ ] 无 P0/P1 缺陷；无明文密钥残留
  - [ ] 设计/需求文档与最终实现一致（文档同步铁律验收）
